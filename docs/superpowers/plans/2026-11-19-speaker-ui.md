# Speaker Interface (step 5a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the minimal 3b speaker screen with the full player (seekable progress, previous, shuffle, 3-state repeat, volume, power), a library limited to player-chosen folders (native folder dialog with an in-game fallback), and a richer item tooltip.

**Architecture:** Queue sequencing (cursor, repeat, shuffle rounds, display order, history) moves into pure `core.queue` code tested with JUnit. The server (`SpeakerPlayback`) only applies those rules, handles the new commands and stores durations reported by the owner's PC (`StreamStartedPayload`). The client gets a new `SpeakerScreen` built from small widgets (player band, library tree, queue list, folders popup) over a source-agnostic `MusicSource` (`core.library`), with the folder list persisted per player in `config/ravecraft-library.json`.

**Tech Stack:** Java 25, Fabric 26.3 (Mojang names), Fabric API, JUnit 5, Fabric GameTests, LWJGL `lwjgl-tinyfd` 3.4.3, Pillow (`tools/textures/gen_textures.py`).

**Spec:** `docs/superpowers/specs/2026-11-19-speaker-ui-design.md`

## Review Focus

1. Queue of one track in repeat `ALL` + shuffle: the next round must replay that track, not stop or spin. Test in Task 2 (`shuffleAllSingleEntryReplays`).
2. Every entry's owner offline in shuffle mode: advancing must return "nothing playable" without looping forever. Test in Task 2 (`shuffleAllAbsentStops`).
3. `SEEK` while paused or with unknown duration: paused stores the position only; unknown duration is ignored. GameTest in Task 6 (`seekWithoutDurationIgnored`, `seekWhilePausedStoresPosition`).
4. Chosen folder deleted or on an unplugged drive: the tree shows it greyed and expanding it does not throw. Test in Task 8 (`missingRootIsMarkedMissing`).
5. A 3b item (no `repeat`, `shuffle`, `pending`, `duration_ms`) loads with defaults `ALL`, `false`, empty, `-1`. Test in Task 4 (`loadsQueueWithoutStep5Fields`).

### Task 2: Queue sequencing in core

**Files:**
- Create: `core/queue/RepeatMode.java`, `core/queue/PlayHistory.java`
- Modify: `core/queue/SpeakerQueue.java`
- Test: `src/test/java/com/ravecraft/mod/core/queue/SpeakerQueueTest.java`, `PlayHistoryTest.java`

**Interfaces:**
- Produces:
  - `enum RepeatMode { OFF, ALL, ONE }`.
  - `record SpeakerQueue(List<QueueEntry> entries, Optional<UUID> current, long positionMs, RepeatMode repeat, boolean shuffle, List<UUID> pending)`.
    - `pending` is the shuffled remainder of the current round, used only when `shuffle`.
    - `EMPTY` uses `ALL`, `false`, `List.of()`.
    - Keep the 3-argument constructor, delegating with those defaults.
  - `Optional<QueueEntry> next(Predicate<UUID> online, boolean natural, RandomGenerator rng)`: the entry to play after `current`, or empty to stop.
  - `SpeakerQueue afterAdvance(UUID nextId, RandomGenerator rng)`: the queue once `nextId` becomes current (`positionMs = 0`, `pending` updated, new round drawn when needed).
  - `SpeakerQueue withRepeat(RepeatMode)` and `SpeakerQueue withShuffle(boolean, RandomGenerator)`.
  - `List<QueueEntry> displayOrder()` and `int nextRoundIndex()` (`-1` when there is no separator).
  - Existing `add`, `remove`, `clear`, `withCurrent`, `withPosition`, `entry` are kept. `clear()` keeps `repeat` and `shuffle`. `add` also inserts the new ids at random positions in `pending` when `shuffle` (overload `add(List<QueueEntry>, RandomGenerator)`; the old signature uses a fixed `new Random(0)` only in tests). `remove` drops the id from `pending`.
  - `nextPlayable(Predicate<UUID>)` is kept for `PLAY` (current if playable, else `next(...)`).
  - `final class PlayHistory`:
    - `push(UUID)`, `Optional<UUID> pop()`, `MAX = 50`; the oldest entry is dropped past 50;
    - `remove(UUID)` purges removed entries.

Rules (spec §4.2), the algorithm the signatures do not fix:
```
next(online, natural, rng):
  if repeat == ONE and natural and current playable -> current
  candidates = shuffle ? pending (in order) : entries after current in list order
  first playable candidate -> it
  round over:
    repeat == OFF -> empty
    shuffle -> the first playable entry of a fresh shuffle of all entries, preferring one != current
               (current only if it is the sole playable entry); empty if none playable
    else    -> first playable entry from the start of the list up to and including current; empty if none
```
`displayOrder`:
- current first;
- then the candidates in order (with `shuffle`: `pending`; without: the entries after current);
- then, in `ALL` only, the separator index and the entries already played this round, in list order (current excluded).

### Task 6: Server playback rules and commands

**Files:**
- Modify: `world/audio/SpeakerPlayback.java`, `network/SpeakerNetwork.java`
- Test: `src/gametest/java/com/ravecraft/mod/gametest/SpeakerPlayerGameTest.java` (declare it in `src/gametest/resources/fabric.mod.json`)

**Interfaces:**
- Consumes: Tasks 2–5.
- Produces:
  - `SpeakerPlayback.command(ServerPlayer, BlockPos, Command, Optional<UUID>, long value)`.
  - `SpeakerPlayback.onStreamStarted(ServerPlayer, int sessionId, long durationMs)`.
  - `stateOf` returns the extended state.
  - History is kept in memory as `Map<SpeakerKey, PlayHistory>` and cleared in `pauseAll`.

Behaviour:
- **Natural end** (`onStreamClose`, finished) no longer removes the entry. Push it to history, call `next(online, true, rng)`, then `afterAdvance` and start; empty → pause at the last entry with `positionMs = 0`.
- **`NEXT`**: same, with `natural = false`.
- **`PREVIOUS`**: if the live position is above 3000 ms, restart the current entry at 0. Otherwise pop the history until an id still in the queue with an online owner is found, and start it at 0. If none is found, restart the current entry.
- **`SEEK`**: needs a current entry with a known duration (otherwise ignored); clamp to `[0, duration]`. While playing: `stop`, store the position, `start`. While paused: store the position only.
- **`VOLUME`**: clamp to `0..100` and save via `be.setData(data.withSettings(settings.withVolume(v)))`. The relay already reads the volume at every chunk.
- **`POWER`**: if `value != 0` differs from the current state, call `be.togglePower()`.
- **`REPEAT`**: `0/1/2` → `OFF/ALL/ONE`, otherwise ignored.
- **`SHUFFLE`**: `withShuffle(value != 0, rng)`.
- **`onStreamStarted`**: if the session is the current one and `durationMs >= 0`, apply `withDuration`.
- **`REMOVE`** of the current entry: `next(online, false, rng)` is computed **before** removing it; then remove, then start that entry if the speaker was playing.
- The RNG is a single `private static final java.util.Random RNG = new Random()` in `SpeakerPlayback`.
- In `SpeakerNetwork`, a separate `TokenBucket` limits `VOLUME` to 8 per second (other commands keep the 10 per second bucket), and the `StreamStartedPayload` receiver is registered.
